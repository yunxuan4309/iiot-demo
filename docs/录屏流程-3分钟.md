# 3 分钟录屏 —— 执行单（照着做就能出片）

> 写于 2026-10-30。目标：一条 **3 分 00 秒以内**、能存进手机、能放 B 站的演示视频。
> 原则：**分段录，别一镜到底** —— 任何一段翻车只重录那一段。
> ⚠️ **开录前先做 `docs/录屏演练-明天开录前.md` 的第零节**：把 PLC 的串口从 COM5（测试桩）切到 **COM7（真表）**，否则"一条链"不成立。

## 一、开录前 10 分钟：检查表（逐项打勾）

### 1.1 服务与环境

```powershell
# 一键起全部（6 个东西，各占一窗）
D:\java\iiot-demo\run-all.cmd
```

| # | 检查项 | 怎么确认 |
|---|---|---|
| 1 | 平台页面能打开 | 浏览器 `http://localhost:8080`，能看到设备列表和曲线 |
| 2 | 数据在动 | 页面上的温度数值每 1~2 秒变化 |
| 3 | TDengine 在跑 | `Test-NetConnection localhost -Port 6030` → True |
| 4 | MQTT 在跑 | `Test-NetConnection localhost -Port 1883` → True |
| 5 | **真传感器插好** | `[System.IO.Ports.SerialPort]::GetPortNames()` 里有 **COM7** |
| 6 | CODESYS 已登录并**运行** | 状态栏「运行」；在线视图 `rTemp` 有值 |
| 7 | ⭐ **CODESYS 的 `Modbus_COM` 用 COM7（真表）** | 不是 COM5！今晚之前是 COM5+测试桩，录屏前必须切到 COM7，否则吹风机不影响 PLC |
| 8 | CODESYS 的 Modbus 主站有数 | `wTempRaw ≈ 室温×10`（如 24.7℃ → 247），且**吹 5 秒会变** |
| 9 | `RtuSlaveMain` 测试桩**已停** | 不再需要，别让它占 COM6/干扰判断 |
| 8 | OPC UA 能读 | `py -3 tools\opcua_probe.py` 能打印 `rTemp` |
| 9 | 三菱工程能打开 | `LD-报警测试.gxw`，白底 11 步 |

> 第 6/7 项如果 `rTemp` 是 0：测试桩没跑（`RtuSlaveMain` 在 COM6）或 COM 口不对。

## 二、分镜脚本（3 分 00 秒）

> 每段单独录、单独保存成 `01.mp4`、`02.mp4`…，最后按顺序拼。

### 段 1｜开场（0:00–0:20）｜20 秒

| 项 | 内容 |
|---|---|
| 画面 | 平台页面 `localhost:8080`（有曲线、有设备列表） |
| 动作 | 鼠标缓慢划过设备列表 → 曲线区 |
| 口播 | 「这是我做的一个工业数据采集与在线监测的最小闭环：南向用 Modbus 从设备取数，北向给平台和 MQTT。三分钟带你走一遍。」 |

### 段 2｜南向真采集（0:20–0:50）｜30 秒

| 项 | 内容 |
|---|---|
| 画面 | 左：真传感器 + 吹风机；右：**CODESYS 在线视图**（`rTemp`、`wTempRaw`） |
| 动作 | 吹风机对着传感器吹 5~8 秒 → `rTemp` 从 2x 往上升 |
| 口播 | 「这是真的 RS485 温湿度变送器，Modbus RTU，COM7，9600-8N1，从站地址 1。它直接接在 PLC 的 485 口上 —— 右边这个数就是 PLC 自己读上来的，吹热风就涨。」 |
| 判据 | 终端数字**明显上升**（一次吹不上去就多吹 3 秒） |

> 💡 录之前先吹到 30℃ 以上，这样镜头里"上升"更明显。

### 段 3｜PLC 自己判断（0:50–1:35）｜45 秒 ⭐ 核心

| 项 | 内容 |
|---|---|
| 画面 | CODESYS 在线视图（`rTemp`、`xAlarm`、`wTempIn`、`wTempRaw`） |
| 动作 | 继续吹 → `rTemp` 上升 → **`xAlarm` 从 FALSE 变 TRUE** |
| 口播 | 「关键在这里：`%IW10/%IW11` 是 PLC 作为 **Modbus RTU 主站**自己从串口读的，`wTempIn` 是 0 —— 说明**采集和判断都在 PLC 里，Java 没参与**。温度超过 32℃，`xAlarm` 变 TRUE。」 |
| 判据 | 同时看到 `wTempRaw` 在变、`xAlarm=TRUE` |

> ⚠️ 这一段的台词别念错："PLC 读设备、PLC 判断"是整条视频的价值主张。

### 段 4｜北向平台（1:35–2:05）｜30 秒

| 项 | 内容 |
|---|---|
| 画面 | 平台页面：曲线 + 告警条 + 数据新鲜度 |
| 动作 | 刷新页面 → 曲线出现刚才那段升温 → 把采集端停 15 秒 → 设备变"数据过期" |
| 口播 | 「数据落到 TDengine，页面上能看到趋势和告警。注意这个：采集端停掉 15 秒，设备会标成"数据过期"变灰 —— 因为库里的质量码是写入那一刻的判定，**过期只能在查询层判断**。」 |
| 判据 | 出现灰色设备或"⚠ 数据过期"字样 |

> 没时间做"停采集"就跳过这半句，只讲曲线。

### 段 5｜工具与协议面（2:05–2:45）｜40 秒

| 项 | 内容 |
|---|---|
| 画面 | ① 三菱 GX Works2（LD + Y0 亮）→ ② Wireshark 抓包帧 → ③ 终端 OPC UA 探针 |
| 动作 | 三张画面各停 8~10 秒，不操作 |
| 口播 | 「工具面：三菱 GX Works2 我会写梯形图、能在仿真器里验证；协议面：这是我抓的 Modbus 报文，一帧里两种字序；同一个 PLC 还有 OPC UA 服务端，客户端能直接读到变量。」 |

> 这三样用**截图 + 放大**也行，不用现场操作，省时间也不容易翻车。

### 段 6｜收尾（2:45–3:00）｜15 秒

| 项 | 内容 |
|---|---|
| 画面 | 回到平台页面 |
| 口播 | 「一句话：**PLC 管现在，Java 管过去和远方**。设备侧我承认是实验室条件，但协议、链路、数据模型都是真的。」 |

## 四、录制工具与设置

| 工具 | 怎么开 | 备注 |
|---|---|---|
| **Windows 自带**（最简单） | `Win + Shift + S` → 点工具栏的**录像**按钮 | 只能录全屏或选区，够用 |
| **Xbox Game Bar** | `Win + G` → 捕获 → 开始录制 | 适合录单个窗口 |
| **OBS**（推荐，如果能装） | 场景 + 窗口捕获 + 麦克风 | 可分段、可加鼠标高亮、可后期剪 |

设置要点：
- 帧率 **30fps** 就够，别用 60（文件大）
- 麦克风增益先试录，避免爆音
- **每段录之前数个 1、2、3**（方便后期对齐）

## 五、翻车应对（录的时候看这张表）

| 现象 | 立刻做什么 |
|---|---|
| 温度不升 | 吹风机靠近 5cm、吹 8 秒；或改用热水杯（安全、稳定） |
| `rTemp` 一直是 0 | 看测试桩是否在跑（COM6）；CODESYS 里看 `Modbus_Server_COM_Port` 状态页 |
| `xAlarm` 不变 TRUE | 阈值是 32，确认 `rTemp` 真超了；超了还不亮就重新 `在线→登录` |
| 页面空白/没数据 | 刷新；看后端窗口有没有报错；确认 6030 在监听 |
| 录屏软件卡死 | **分段录的价值**：只重录当前段，前面不动 |
| 说错词 | 别剪辑里硬救，直接重录那一段（3 分钟片子重录一段只要 40 秒） |
| 有电话/通知弹窗 | 开录前开"专注助手"，或直接拔网线（不影响本地演示） |

## 六、录完做什么（10 分钟）

1. **导出**：1920×1080 mp4，命名 `iiot-demo-3min-2026xxxx.mp4`
2. **备份到手机**：用微信"文件传输助手"或数据线，**手机相册能播**才算成功
3. **检查时长**：必须 **≤ 3:00**（超了就砍段 5 或段 2）
4. **听一遍**：有没有爆音、有没有把"蓝色"说成"绿色"（GX 用蓝色表示导通）
5. **（可选）传 B 站**：标题带 `Modbus / OPC UA / 工业数据采集`，简介放 GitHub 链接
6. **（可选）加字幕**：B 站自动字幕校对一遍，重点词别错（"字序""质量码""刷新频率"）
