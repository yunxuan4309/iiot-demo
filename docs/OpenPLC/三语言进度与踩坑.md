## 二、⭐ 最重要的一条：**新建的 Program 不会自动执行**

### 现象

新建 `temp_check`（ST）→ 编译**成功** → 但 Console 里有一行：

```
No instance found for program 'temp_check', skipping debug variable parsing.
```

而且：
- Debugger 面板看不到它的变量
- 变量表的 **`Debug` 列是空的**（没法强制）

### 根因

> **`Programs` 下新建的 POU 不会自动挂到任务（Task）上。**
> IEC 61131-3 的运行模型是：**Task（周期）→ Instance（程序实例）**。没有 Instance，程序就只是"一段被编译过的代码"，**永远不执行**。

### 解法

打开左侧 **`Resource`** 页面 → 找到 **`Instances`** 表 → 加一行：

| Name | Program | Task |
|---|---|---|
| `instance0` | `main` | `task0` |
| **`instance1`** | **`temp_check`** | `task0` ← 加这行 |

（`task0` 是默认的 `Cyclic / T#10ms / Priority 1`）

### 对比：CODESYS 里是同一件事，但可视化

| | CODESYS | OpenPLC |
|---|---|---|
| 在哪看"会不会执行" | 设备树 **`MainTask → PLC_PRG`** | `Resource → Instances` 表 |
| 默认状态 | **默认就挂好** | **要手动加** |

> ⭐ **面试口径**：「**程序编译通过 ≠ 会执行。** 两个工具都要求程序挂到 Task 上才进扫描周期 —— CODESYS 是可视化任务树，OpenPLC 要在 Resource 里配 Instances，**不配就静默不跑**，很容易误判成'代码写错了'。」

## 三、踩到的坑（按发生顺序）

### 坑 1：变量类型建成了 `DINT`

- 现象：新建 `temp_check` 时，`rTemp` 的类型默认成了 **`DINT`（32 位整数）**。
- 问题：温度是**模拟量**，`DINT` 存不了 `25.5` 这种小数；而且 **CODESYS 那边是 `REAL`**，类型不一致就没法对比。
- 解法：点 `Type` 单元格 → 改成 **`REAL`**。
- **教训**：**`DINT` 是整数、`REAL` 是浮点**，工业里的温度/压力/流量一律 `REAL`。

### 坑 2：新建 Program 不执行（见 §二，最核心的一个）

### 坑 3：界面 bug —— 删掉 Instances 最后一行后，`+` 点不了

- 现象：误点 `−` 把 `instance0/main` 那行删了，表变空之后 **`+` 按钮失效**，加不回来。
- 解法：**直接改文件**（这是纯文本工程的优势）：

```powershell
cd D:\java\iiot-demo
git checkout -- project.json     # 恢复已知正确状态
# 然后在 instances 数组里手加 instance1
```

### 坑 4：删完之后**自动存盘了**

- 现象：以为"没保存就没事"，但 `git status` 显示 `M project.json`，且 `instances` 已经是**空数组**。
- 结论：**编辑器会在操作后落盘**，别指望"不点保存就安全"。
- **真正的安全带是 git**：`ceadce0` 那次提交救了回来。
- **教训**：**动配置前先确认最后一次提交是干净的**；纯文本工程 + git = 可回滚。

### 坑 5：窗口关了但**进程还在**

- 现象：点了关闭，但任务管理器里还有 **4 个 `OpenPLC Editor`** 进程（合计约 **726 MB**，Electron 多进程）。
- 风险：**残留进程里是"错的内存状态"，一旦它保存就会覆盖磁盘上的正确文件**。
- 解法：确认进程真退出（或任务管理器结束任务）；**重开前先确认旧进程没了**。

### 坑 6：每次编译都去 GitHub 拉库，网络不通就报 Error（**但不影响编译**）

```
Warning: could not install open62541 (OPC-UA server) from github.com ... (exit 1)
Error installing Git Library: ... dial tcp 20.205.243.166:443: connectex: 连接超时
Warning: could not install Settimino (S7Comm server) from github.com ... (exit 1)
```

| 项 | 说明 |
|---|---|
| 拉的是什么 | `open62541`（OPC UA 服务器）+ `Settimino`（S7Comm 服务器），**每次 Build 都尝试** |
| 为什么失败 | **连不上 GitHub**（`20.205.243.166:443` 超时） |
| **有影响吗** | ❌ **没有**。工具自己说："Continuing — the compile will fail with a missing header **if it was genuinely needed**"；**编译照样成功** |
| 代价 | 每次编译**多等约 40 秒**（两次 × 20 秒超时） |
| 要管吗 | **不用管**。本 demo 用 **Modbus**，不用 OPC UA / S7Comm |

> 📌 **记一笔**：编译慢 40 秒是正常的，不是你的问题。

### 坑 7：程序运行时**代码编辑器变只读**

- 现象：双击代码行里的值想改 → 提示 `Cannot edit in read-only editor`。
- 原因：**程序在跑的时候禁止改代码**（防止改坏正在执行的逻辑）—— 这是**保护机制**，不是 bug。
- 解法：改值走**变量表的 `Debug` 列**（见 §四）。

### 坑 8（不是坑）：ST 里**空格不必须**

- `xAlarm :=rTemp > 80.0;` **语法合法**，能编译。
- 但**建议加空格**：① 可读性 ② **和 CODESYS 那段一字不差**，对比截图才有说服力。

## 四、日常速查

| 要做什么 | 怎么做 |
|---|---|
| 新建程序块 | 左侧顶部 **`+`**（或右键 `Programs` → 新建 POU）；**语言选 ST** |
| **让新程序执行** | **`Resource`** → `Instances` 表加一行（Program + Task） |
| 编译 | 左侧 **⚙**（或 ▶）；Console 找 `Compilation complete` |
| **强制/改值** | 变量表最右 **`Debug` 列**的图标（**不是**双击代码行 —— 运行时只读） |
| 看实时值 | 代码行里**绿底的值**（`xALARM TRUE := rTemp 90.000000 > 80.0;`） |
| 看变量全表 | 底部 **`Debugger`** 面板 → `Variables`（名字带程序前缀，如 `temp_check.rTemp`） |
| 检查实例是否生效 | Console 里**不该再有** `No instance found for program '...'` |
| 加 FBD 程序 | `+` → 语言选 **FBD** → 从**左侧竖条工具箱**拖 `Block` / `Input Variable` / `Output Variable` → **长按圆点拖线**连接 |

## 六、⭐ FBD 到底怎么玩（**界面看不出来，全靠逆向软件才搞清**）

> 这一节花了近 1 小时才摸出来。**记下来，下次 5 分钟能做出来。**
> 软件里几乎没有任何提示 —— 下面每一条都是从 `app.asar` 里读出来的。

### 6.1 数字/变量绑定的**入口在"左侧竖排"**，不在画布

FBD 画布上**只有缩放控件**（`+` `−` `⛶`），**没有任何"添加元素"的按钮**。

真正入口是 **左侧那排图标竖条** —— 当 FBD 编辑器激活时，会**多出 5 个图标**（鼠标悬停看 tooltip）：

| 图标 tooltip | 内部类型名 | 作用 |
|---|---|---|
| `Block` | `block` | 放功能块（`GT`、`ADD`…） |
| **`Input Variable`** | `input-variable` | ⭐ **放输入（变量或常量）** |
| **`Output Variable`** | `output-variable` | ⭐ **放输出变量** |
| `Connector` | `connector` | 连接器（跨图跳转） |
| `Continuation` | `continuation` | 续接点 |

**用法：从竖条把它拖到画布上。**

> ⚠️ **坑**：直接"点"它们没反应，**必须拖拽**。
> ⚠️ **坑**：在 `Library` 面板搜 `var` 只会搜到 `ARRAY_VAR` 这类**函数**（数组方差计算），**不是**变量元素 —— **别拖错**（我拖错过一次）。

### 6.2 连线：**长按圆点拖到另一个圆点**

| 圆点位置 | 角色 |
|---|---|
| 方块**右边** | **输出（源）** |
| 方块**左边** | **输入（目标）** |

**长按源点 → 拖 → 松手在目标点。**

> ⚠️ **坑**：如果拖到**空白处**，线会**无限跟着鼠标跑**，不会创建变量 —— 必须先有目标方块，或者先从工具箱拖出变量方块。

### 6.3 常量怎么输

拖一个 `Input Variable` 进来，**直接填 `80.0`**（显示成**橙色**，软件自动识别为常量；变量是**黑色**）。

### 6.4 绿色 = TRUE（**和 LD 的"能流"同一个约定**）

| `rTemp` | `OUT → xAlarm` 连线 | `xAlarm` 方块 | 含义 |
|---|---|---|---|
| `0.000000` | 灰 | 蓝框 | FALSE |
| **`90.000000`** | **🟢 绿** | **🟢 绿框** | **TRUE** |
| **`75.000000`** | 灰 | 蓝框 | FALSE |

> **这就是 FBD 里"读值"的方式**：不用看变量表，**看线的颜色**。

### 6.5 文件格式（纯文本，可手改）

`pous/programs/temp_fbd.fbd` = ST 风格头 + **JSON**：

```
PROGRAM temp_fbd
  VAR
    rTemp : REAL;
    xAlarm : BOOL;
  END_VAR

{
  "name": "temp_fbd",
  "rung": {
    "edges": [ { "source": "...", "target": "...", "sourceHandle": "OUT", "targetHandle": "IN1" } ],
    "nodes": [
      { "type": "block",  "data": { "variant": { "name": "GT", ... } } },
      { "type": "input-variable",  "data": { "variant": "input",  "variable": { "name": "rTemp" } } },
      { "type": "output-variable", "data": { "variant": "output", "variable": { "name": "xAlarm" } } }
    ]
  }
}
END_PROGRAM
```

**节点类型枚举**（从软件代码里挖出来的）：
```js
["block","comment","connector","connection","input-variable","output-variable","inout-variable"]
```

### 6.6 新增的两个坑

| # | 坑 | 说明 |

| **9** | **FBD 的变量绑定入口藏在左侧竖条** | 画布上找不到任何"加变量"按钮；`Library` 里搜 `var` 会拖错成 `ARRAY_VAR`。**正确答案：左侧竖条的 `Input Variable` / `Output Variable`，拖到画布** |
