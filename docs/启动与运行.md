# 启动与运行

> 五个可执行程序、三种启动方式、一个必须记住的顺序。**改过代码先 build。**

---

## 一、先认清：一共 **5 个程序**

| 程序 | main class | 作用 | 入口 |
|---|---|---|---|
| **仿真从站** | `com.iiot.collector.SimSlaveMain` | 造 Modbus 设备（多台 / 造故障） | `collector\run-slave.cmd` |
| **四字序探测** | `com.iiot.collector.ProbeMain` | 读寄存器 / 猜字序 / 写线圈 | `collector\run-probe.cmd` |
| **单设备采集** | `com.iiot.collector.CollectMain` | 一台设备，逐轮打印 | `collector\run-collect.cmd` |
| **多设备采集** ⭐ | `com.iiot.collector.MultiDeviceMain` | 主力：虚拟线程 + 质量码 + 告警 + MQTT + 写库 | `collector\run-multi*.cmd` |
| **监测平台** | `com.iiot.platform.PlatformApplication` | Spring Boot，`localhost:8080` | `platform\run-platform.cmd` |

前 4 个是普通 Java `main`（`collector` 模块），第 5 个是 Spring Boot。

---

## 二、⚠️ 启动顺序（库必须先起）

```
① 库      device\tdengine\start-tdengine.cmd          6030 / 6041
② 北向    device\mqtt\start-mqtt.cmd（可选）           1883
③ 设备    collector\run-slave.cmd --port 1502 --devices 10
④ 采集    collector\run-multi-tdengine.cmd --fanout 10 --duration 60
⑤ 页面    platform\run-platform.cmd                   http://localhost:8080
```

**为什么不能乱**：采集端启动时会连 TDengine（`--store tdengine` 时），库没起会直接抛
`ConnectException`；平台连不上库会返回 **503 + 可读提示**（不会白屏）。

## 三、改代码之后必须 build

```powershell
cd D:\java\iiot-demo
.\mvnw.cmd -o -DskipTests package
```

产物：

| 产物 | 大小 |
|---|---|
| `collector\target\collector-0.1.0-SNAPSHOT.jar` | ≈ 1.4 MB（shade 单文件，含 j2mod + paho） |
| `platform\target\platform.jar` | ≈ 23 MB（Spring Boot 可执行 jar） |

> 离线可构建（`-o`）：j2mod / paho / Spring Boot 3.2.5 都已在本地 `.m2`。

## 四、三种启动方式

### 方式 A：双击 `.cmd`（最省事）

见上面第二节。参数直接跟在后面：

```
collector\run-multi.cmd --fanout 100 --duration 60
collector\run-multi.cmd --help          ← 看全部参数
collector\run-slave.cmd --help
```

### 方式 B：命令行（脚本里就是这一行）

```powershell
cd D:\java\iiot-demo

# 多设备采集（写 TDengine）
java -Dstdout.encoding=UTF-8 -Djava.net.preferIPv6Addresses=true `
  -cp collector\target\collector-0.1.0-SNAPSHOT.jar `
  com.iiot.collector.MultiDeviceMain --fanout 10 --duration 60 --store tdengine

# 平台
java -Dstdout.encoding=UTF-8 -Djava.net.preferIPv6Addresses=true `
  -jar platform\target\platform.jar
```

### 方式 C：IDEA

1. **先 build 一次**：右侧 Maven 面板 → `iiot-demo` → Lifecycle → `package`
2. 打开目标类（如 `MultiDeviceMain.java`）→ 点行号旁绿色箭头 → **Modify Run Configuration**
3. 按下表配：

| 配置项 | 值 | 是否必须 |
|---|---|---|
| **Main class** | `com.iiot.collector.MultiDeviceMain` | 必须 |
| **VM options** | `-Djava.net.preferIPv6Addresses=true -Dstdout.encoding=UTF-8` | ⚠️ **必须** |
| **Program arguments** | `--fanout 10 --duration 60 --store tdengine` | 视情况（不填 = 一直跑，Ctrl+C 停） |
| **Working directory** | `D:\java\iiot-demo` | 建议 |

> ⚠️ **IDEA 里最常见的坑**：只点绿色箭头、忘了加 VM options
> → 采集端报 `ConnectException: localhost:6041`，而 `curl` 却通 —— 就是 IPv6 那个坑。

## 五、常用参数速查

### 仿真从站 `run-slave.cmd`

| 参数 | 默认 | 说明 |
|---|---|---|
| `--port` | 1502 | 端口（**不用 502**：<1024 在 Linux 要 root） |
| `--devices` | 1 | 从站台数（unitId 1..N） |
| `--base-temp` | 62.0 | 温度基准值 |
| `--spike-prob` | 0.005 | 单点尖峰概率（演示告警去抖调到 **0.10**） |
| `--hang-unit` | 0 | 让该 unitId **卡死**（连接在、不回包，坑 5） |
| `--hang-after` | 0 | 启动后多少秒再卡死 |
| `--write-delay-ms` | 0 | 写应答延迟（超过读超时即复现坑 4） |

### 多设备采集 `run-multi.cmd`

| 参数 | 默认 | 说明 |
|---|---|---|
| `--fanout` | 1 | 设备台数（从点表模板扇出） |
| `--duration` | 0 | 运行秒数（0 = 一直跑） |
| `--cycles` | 0 | 每台跑几轮（0 = 不限） |
| `--timeout` | 2000 | 读超时 ms |
| `--interval` | 0 | 覆盖点表里的周期 |
| `--store` | counting | `counting`（不落盘）/ `tdengine` |
| `--alarm` | 关 | 启用告警引擎（规则见 `resources/alarms.properties`） |
| `--alarm-ab` | 关 | A/B：同批数据同时喂「去抖」与「不去抖」两个引擎 |
| `--northbound` | none | `mqtt` 开启北向发布 |
| `--verbose` | 关 | 设备多时也逐台打印 |

## 六、常见故障对照

| 现象 | 原因 | 解决 |
|---|---|---|
| `ConnectException: localhost:6041`，但 `curl` 通 | **IPv6**：WSL 只把 TDengine 暴露在 `[::1]`，JVM 默认偏好 IPv4 | 加 `-Djava.net.preferIPv6Addresses=true`，或 URL 写成 `http://[::1]:6041` |
| `端口 1502 起不来` | 上一个从站没退干净 | `netstat -ano \| findstr :1502` → `Stop-Process -Id <pid>` |
| 页面 503 + `TDengine 不可用` | 库没起 | `device\tdengine\start-tdengine.cmd` |
| 采集端打印乱码 | 缺 UTF-8 | 脚本已带 `-Dstdout.encoding=UTF-8`；IDEA 里要手动加 |
| 平台启动即退出、端口占用 | 8080 被占 | `netstat -ano \| findstr :8080` |
| JVM 跑完不退出（MQTT） | Paho 线程非守护 | 已在代码里 `close()`；若自己改代码记得保留 |

## 七、停止

| 目标 | 做法 |
|---|---|
| 从站 / 采集端 / 平台 | 对应窗口 `Ctrl + C` |
| TDengine | `device\tdengine\stop-tdengine.cmd` |
| Mosquitto | `device\mqtt\stop-mqtt.cmd` |
| 全部 | 关掉所有窗口 + WSL 里 `systemctl stop mosquitto`（TDengine 用脚本停） |

> 数据不丢：TDengine 数据在 WSL 的 `~/tdengine/data`，重启后还在。
