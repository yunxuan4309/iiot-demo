# 工业设备数据采集与在线监测

> **一句话**：南向 **Modbus（TCP/RTU）** → **统一数据模型（含质量码）** → **时序库** → **Web 监测页**，全链路自建、可一条命令复现。

## 解决什么问题

工业数据与互联网数据的三点差别，也是本项目的三个工程约束：

| 差别 | 约束 |
|---|---|
| 数据在**二进制寄存器**里 | 32 位值跨两个 16 位寄存器，**四种字节序**（ABCD/CDAB/BADC/DCBA）；字序必须按点位配置，不能硬编码 |
| 数据**可能不可信** | 断线不能补 0（下游会把"0℃"当真值）→ 必须带**质量码** GOOD/STALE/BAD |
| 点位约定在**厂家手册**里 | 地址、类型、字序、量程全部来自**配置**，代码里不出现任何设备的私有约定 |

## 架构

```
  仿真从站 × N / 真传感器 × 1
        │  Modbus TCP（1502）／ RTU（RS485）
        ▼
  collector（Java 21）
        DeviceDriver 抽象 ─ TcpModbusDriver ✔ / RtuModbusDriver（接口已留）
        DeviceSampler ─ 质量码 GOOD/STALE/BAD ＋ 量程校验
        每设备一条虚拟线程 ＋ 独立驱动 ＋ 失败退避
        │  批量 REST（攒 500 点 / 500 ms）
        ▼
  TDengine 3.3（WSL2 内免 root）
        超级表 telemetry ＋ 每「设备 × 点位」一张子表
        │  SQL（只读）
        ▼
  platform（Spring Boot ＋ ECharts）
        /api/overview · /api/latest · /api/series
```

## 实测指标（100 台 × 4 点位 × 1 Hz × 60 s）

| 指标 | 值 |
|---|---|
| 采集完整率 | **100.00%**（24000 / 24000，GOOD 24000） |
| 入库吞吐 | **388 点/秒**（195 批，每批约 123 点 ⇒ HTTP ≈ 3 次/秒） |
| 采集延迟 | **P50 1.27 ms · P95 4.14 ms · P99 9.95 ms** |
| 写入失败 / 队列丢弃 | **0 / 0** |
| 断线演练 | 值**保留上次**并标 **STALE**（不是 0）；采集器**不崩**，完整率从 100% 平滑降到 61.5% |
| 字序证伪 | 同一帧 `0x704A/0x4280`：CDAB 解出 **64.22℃**，ABCD 解出 **2.5e29** |

## 八个坑（每条都是「我以为是 X，其实是 Y」）

| # | 坑 | 结论 |
|---|---|---|
| 0 | **假数据一眼假** | `random()` 是锯齿；真信号要有惯性（一阶低通）＋漂移＋尖峰＋采样抖动 |
| 1 | **寄存器字序** | Modbus 只规定寄存器 16 位，**不规定 32 位怎么拆**；国内仪表常见 CDAB |
| 2 | **40001 vs offset 0** | 手册的 `40001` 是 1 基惯用编号，报文传 0 基。混了**不是读错值，而是永远超时**（报文里 `9C 41` = 40001） |
| 3 | **断线不是 0** | 补 0 比没数据更危险 → 必须显式标 STALE（旧值）/ BAD（无值） |
| 4 | **写不幂等** | 超时重发会让"触发型"写执行两次；本 demo 的可写点只有线圈置位（天然幂等），故**只记录未制造** |
| 5 | **单设备拖垮采集** | 三重隔离：线程（虚拟线程）／连接（每设备独立 driver，因为 `read()` 是 synchronized）／时间（读超时）；失败 1×2×4×8 退避 |
| 6 | **时间基准** | TDengine 存 UTC、返回带 `Z`；前端不转时区整张图偏 8 小时。采集端用 **epoch 毫秒**写入避免歧义 |
| 7 | **告警泛滥** | 实测：10 分钟 3 台设备 **836 个越限采样点，但只有 10 次真实越限事件 = 放大 83.6 倍**；正确做法＝持续时间去抖 ＋ 回差 ＋ 分级抑制 |

## 技术栈与取舍

| 选择 | 为什么 |
|---|---|
| Java 21 **虚拟线程** | 100 台设备＝100 条线程，平台线程太重 |
| **j2mod** | 主站＋从站一体，能自己造仿真设备验证协议 |
| **纯文本点表** | 厂家点位约定不该写进代码 |
| **TDengine** | 工业圈常见；超级表＋子表天然贴合「设备×点位」 |
| **REST 而非 JDBC** | 免 native 库、可跨 WSL／SSH 隧道；返回自带 `column_meta` |
| **ECharts 本地副本** | 离线可跑，不依赖 CDN |

## 边界（诚实的部分）

- **不是生产系统**：单机、无认证、无高可用、无联锁
- **真传感器尚未接入**（等快递）：但已验证两类数据源（自写仿真从站 + **CODESYS 软 PLC 真实运行时**）与 **ST/LD/FBD 三语言**；`RtuModbusDriver` 已实现并**用虚拟串口实测通过**（25.6℃ / ABCD），到货只改 `comPort`
- **北向 MQTT 已通**：`iiot/{device}/{point}` · QoS 1 · retain=true（新订阅者立刻拿到最新值）；**但没开认证**，demo 用 `allow_anonymous`
- **告警只做判断不做通知**：引擎已实现并 A/B 验证（86→12 条），但短信/企微与同源合并未做
- **只有 4 个点位**：够验证链路，不够覆盖真实产线
