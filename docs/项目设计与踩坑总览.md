# 项目设计与踩坑总览（一页看懂 / 面试前必读）

> 最后更新：**2026-10-28** · 50 提交 · 对应硬件：艾克姆 IKM10000WS01 温湿度变送器（RS485）

---

## 一、一句话定位

> **一个"设备数据采集 → 时序存储 → 在线监测"的最小闭环**，用来搞清「工业软件 vs 电商」的差别：
> **电商里 Java 是老板（业务逻辑在它手里）；工业里 Java 是记录员（决策在设备侧，Java 只负责看和存）。**

**不是生产系统**：单机、无认证、无高可用、无联锁。目标是**可演示 + 可讲清原理**。

## 三、8 个关键设计决策（每条都有"被否决的备选"）

| # | 决策 | 为什么 | 被否决的备选 |
|---|---|---|---|
| **1** | **点表配置化**（区域/偏移/类型/字序/缩放/量程全在 properties） | 换设备**只改配置不改代码** —— 已用 CODESYS 真 PLC + 真传感器验证过两次 | 每种设备写一个驱动类（设备一多就爆炸） |
| **2** | **字序是配置项，不是代码常量** | Modbus 只规定寄存器 16 位，**不规定 32 位怎么拆**。同一批设备可能 CDAB，也可能 ABCD | 硬编码 CDAB（等于把一台设备的行为当协议标准） |
| **3** | **断线打质量码，绝不补 0** | 补 0 会让下游把"0℃"当真温度 —— **比没有数据更危险** | 补 0 或补最后一次值（都会骗人） |
| **4** | **按物理链路复用连接**（`DriverRegistry`） | **一个 COM 口只能被打开一次**；RTU 半双工必须请求串行 | 每台设备一个驱动实例（RTU 上第二台就报错） |
| **5** | **每台设备一个虚拟线程** | 阻塞式 Modbus 读写 + 设备级隔离；JDK21 虚拟线程成本极低 | 线程池（设备数一多就排队）；单线程轮询（一台挂死全崩） |
| **6** | **过载保护靠"队列 + 丢弃计数"，不靠阻塞** | 采集不能因为写库慢而停；宁可丢点也要保证采样节奏 | 阻塞写入（TDengine 一慢，整条链路卡死） |
| **7** | **数据新鲜度在查询层算**（`ageSeconds`/`stale`） | 库里存的 quality 是"写进去那一刻"的；**采集端停了它仍然是 GOOD** | 在采集端标记（它自己挂了没法报告）；在库里存（不知道以后有没有人写） |
| **8** | **PLC 的决策和 Java 的记录分离** | 判断（`xAlarm := rTemp > 32`）放在 PLC；Java 只搬运和存储 | 在 Java 里判断（断网/服务挂了设备就失去保护） |

## 四、踩过的坑（分类 + 每条的现象/根因/教训）

### A. 协议层

| 坑 | 现象 | 根因 | 教训 |
|---|---|---|---|
| **1 寄存器字序** | 读出来是 1e29 这种天文数字 | 32 位值拆成两个 16 位寄存器的顺序有 4 种（ABCD/CDAB/BADC/DCBA） | **字序必须实测**。CODESYS 实测 **CDAB**（低字在前）；RTU 测试桩实测 **ABCD** |
| **2 40001 vs offset 0** | 全错一位 | 手册的 `40001` 是**1 基惯用编号**，协议报文传的是 **0 基偏移** | 填点表时减 1 |
| **3 用整数验字序 = 白验** | 两种字序解出同一个数，以为对了 | `90.0 = 0x42B40000`，**低 16 位是 0**，两种解释都成立 | 必须用**低 16 位非零**的值：`90.1` / `25.6`。**带小数不够，`25.5` 也失败** |
| **4 FC03 vs FC04** | 返回异常码 `01`（非法功能） | 设备只实现了保持寄存器，没实现输入寄存器 | **会看 Modbus 异常码**：`01`=非法功能、`02`=非法数据地址 |
| **5 一个 COM 口只能开一次** | 第二台设备连不上 | 串口是独占资源，RTU 半双工还需请求串行 | 按**物理链路**复用，不是按设备 |

### B. 设备层（RS485 现场问题 —— 这些是真正的"工业味儿"）

| 坑 | 现象 | 根因 | 教训 |
|---|---|---|---|
| **6 A/B 接反** | 完全读不到 | 485 差分信号接反 | **接反不烧，只是读不到**；读不到第一件事就是**对调 A/B** |
| **7 没共地** | 通电后指示灯不亮 / 读不到 | 差分信号的判定需要**共同的地参考** | GND 要接**两个地方**：电源负 + 转换器 GND |
| **8 寄存器顺序猜反** | 温度显示 64.6℃（其实是湿度） | 假设 `offset0=温度`，实测 **`offset0=湿度`** | **先读原始值再判断**：646/248 哪个像温度？ |
| **9 I/O 地址是设备分配的** | CODESYS 里 `xAlarm AT %QX0.0` 编译运行都正常，Modbus 永远读到 0 | 实际通道在 **`%QX20.0`**（前面字区占了字节 0~19） | **先看设备映射表，再写 AT 地址**（顺序不能反）。官方也建议在设备编辑器里绑定 |

### C. 工程层

| 坑 | 现象 | 根因 | 教训 |
|---|---|---|---|
| **10 单设备拖垮采集** | 一台挂死，别的也超时 | 同步阻塞 + 共享连接 | 三重隔离（线程/连接/超时）+ 失败退避 |
| **11 告警泛滥** | 一抖就报，几十条 | 单点越限就报，没有去抖/回差 | 去抖 + 回差 + 分级 + 质量码门禁 → **A/B 实测 86 条压到 12 条（-86%）** |
| **12 采集端停了页面看不出来** | "63.45℃ 一切正常"，其实是 3 小时前的数据 | **库里 quality 是写入时的判定，不会因为没人写而变 STALE** | **新鲜度必须在查询层算**（`ageSeconds > 3×周期 → stale`） |
| **13 时间基准** | 曲线整体偏 8 小时 | 库里存 UTC、前端不转时区 | 传输层统一 UTC（带 `Z`），只在展示层转本地时间 |

### D. 工具链 / 方法论

| 坑 | 现象 | 教训 |
|---|---|---|
| **14 cmd 里的 `>` 打断 wsl 命令** | `syntax error near unexpected token 2` | **`.cmd` 里别在 wsl 参数中写 `>`** —— 重定向放 WSL 侧的 `.sh` 里 |
| **15 PowerShell 拆坏 `-D` 参数** | `ClassNotFoundException: /encoding=UTF-8` | 用 `.cmd` 包装调 java，或在 PS 里给参数加引号 |
| **16 CODESYS 在线时工程只读** | 改不了变量、点不动 I/O 映射 | **先 `在线 → 注销`** 才能改 |
| **17 改值要"写入值"** | 双击改成 90，PLC 里还是旧值 | CODESYS 有**准备值 / 写入值**两回事：`调试 → 写入值`（Ctrl+F7） |
| **18 ⭐ 排障顺序错了，白扫 16 组参数** | 扫了 8 波特率 × 2 校验 × 8 地址全无回应 | **A/B 根线还没接**！**排障不是"试更多可能性"，是"按依赖顺序逐层确认"**：物理 → 电平 → 参数 → 数据 |
| **19 CODESYS 工程忘记保存** | 改了 3 小时，磁盘上还是前天的版本 | **CODESYS 不会自动保存**（编译/下载都不保存），**必须 Ctrl+S** |
| **20 写操作不校验** | 端口没起来，`write()` 照样报"成功" | **写操作必须读回确认**（写不幂等，超时重发可能动作两次） |

## 七、面试用的三个版本

### 30 秒
> 「我做一个工业数据采集的小闭环：真 RS485 温湿度传感器 + 一台软 PLC，采到的数据进时序库、上页面。
> 重点不是"跑起来"，而是**把工业现场的坑做成工程约束**：质量码、字序可配、告警去抖、数据新鲜度。」

### 3 分钟
加这三句：
> 「① **换设备只改点表** —— 我用同一套采集端读过自写仿真从站、CODESYS 真 PLC、真传感器三类设备，代码一行没改。
> ② **判断在设备侧** —— PLC 里写 `xAlarm := rTemp > 32`，我用吹风机加热到 34.2℃，PLC 判定报警；降到 31.5℃ 自动解除。**Java 全程没做判断**。
> ③ **断线不是 0** —— 补 0 会被当成真实温度，所以我用质量码 + 查询层的新鲜度判定，让"采集端挂了"能显式暴露。」

### 被追问时的深挖点
- **字序**：为什么必须实测？`90.0` 验不出来，要 `90.1`（低 16 位非零）
- **一条 COM 口只能开一次** → 按物理链路复用驱动
- **排障顺序**：物理 → 电平 → 参数 → 数据（我在这上面栽过，白扫 16 组参数）
- **新鲜度为什么不能在采集端做**：采集端自己挂了没法报告

- **西门子 S7-1200**：❌ 不买 —— 软件都装不了，买了也用不上

- **ESP32 + OpenPLC**：❌ 对这份 JD 无加成（不在名单里）
- **结论**：**先用仿真器把语言练熟**（¥0），需要真机再议
