# 工业通信协议与工厂系统 —— 面试速查

> 用途：补 JD 资格第 4 条（**Modbus TCP/IP、Profinet、EtherNet/IP、OPC UA** + **MES、SCADA、EAM/CMMS**）
> 原则：**每个都给你"一句话答案"**，能在面试里说出口；不追求背参数。

---

## 〇、先记住这张"分层图"（ISA-95）

```
L4  业务层   ERP（SAP / 用友）            ← 订单、采购、财务
L3  制造运营 MES（制造执行）              ← 工单、批次追溯、质量、OEE
L2  监控层   SCADA / HMI                  ← 画面、报警、历史、报表
L1  控制层   PLC / DCS                    ← 逻辑、联锁、回路调节
L0  现场层   传感器 / 执行器 / 变频器       ← 测量与动作
        ↑ 层与层之间靠"工业通信协议"连接
```

**面试最容易被问**：「MES 和 SCADA 有什么区别？」
> **SCADA 管"看"（监控实时状态），MES 管"做"（生产订单怎么执行、批次怎么追溯）。**
> SCADA 关心"现在温度多少、报警没"；MES 关心"这批料做了多少、良率多少、用的哪批原料"。

## 一、六个协议，一句话定位

| 协议 | 一句话 | 谁主导 | 典型周期 |
|---|---|---|---|
| **Modbus RTU** | 串行总线上的"主问从答"，**1979 年的老古董，但最简单最通用** | Modicon（施耐德） | 10~100 ms |
| **Modbus TCP** | 把 Modbus 报文套进 TCP/IP，端口 **502** | 施耐德 / 社区 | 10~100 ms |
| **Profinet** | 西门子的工业以太网，**RT（实时）/ IRT（等时实时）** | 西门子（PNO） | RT 1~10 ms，**IRT < 1 ms** |
| **EtherNet/IP** | 罗克韦尔的工业以太网，基于 **CIP** 对象模型 | 罗克韦尔（ODVA） | 1~10 ms |
| **EtherCAT** | 倍福的"飞读飞写"，**从站芯片硬件处理**，最快 | 倍福（ETG） | **< 100 µs** |
| **OPC UA** | **不是实时协议**，是"**带语义的跨系统数据交换**"标准 | OPC 基金会（IEC 62541） | 毫秒~百毫秒 |

---

## 二、⭐ 最重要的一个区别：**Modbus 没有"语义"，OPC UA 有**

这是**最能拉开差距**的一句话：

> **Modbus 只规定"第 40001 号寄存器里有两个字节"，它不知道那是温度、湿度、还是电机转速。**
> **语义完全靠人约定（写进点表/手册）。**
>
> **OPC UA 有"信息模型"** —— 变量带**名字、数据类型、工程单位、层级关系**，客户端可以**自描述地浏览**：
> `Device.Sensor01.Temperature = 24.7 °C`
> **不看手册也能读懂。**

**打个比方**：
- **Modbus 像"快递柜编号"** —— 你知道 12 号柜子里有东西，但不知道是什么
- **OPC UA 像"带标签的快递"** —— 上面写着"易碎、25.3℃、来自车间A"

**⇒ 所以：现场设备通信用 Modbus/Profinet（快、简单），跨系统集成用 OPC UA（能自解释、能跨平台）。**

## 三、实时性分层（被问"为什么不都用 OPC UA"就答这个）

```
快 ┌ EtherCAT        < 100 µs   运动控制（多轴同步）
   │ Profinet IRT    < 1 ms     精密同步、伺服
   │ Profinet RT     1~10 ms    一般 I/O、变频器
   │ EtherNet/IP     1~10 ms    罗克韦尔系 I/O
   │ Modbus TCP      10~100 ms  采集、监控（够用）
慢 └ OPC UA          毫秒~百毫秒  跨系统、上云、MES 集成
```

**为什么 Modbus 慢还活着**：
- **实现成本极低**（几十行代码就能当主站）
- **跨厂商**（不是谁的私有协议）
- **采集场景不需要毫秒级** —— 温度 1 秒采一次完全够

**⇒ 我在项目里选 Modbus，就是因为它"跨厂商 + 免费 + 我的真传感器就是 Modbus RTU"。**

## 四、Profinet / EtherNet-IP / EtherCAT 三者的本质差别

| | **Profinet** | **EtherNet/IP** | **EtherCAT** |
|---|---|---|---|
| 厂商 | 西门子 | 罗克韦尔 | 倍福 |
| 数据模型 | GSDML 文件描述设备 | **CIP 对象模型**（对象/实例/属性） | 对象字典（CoE） |
| 实时实现 | **RT 用软件栈 / IRT 用专用 ASIC** | **UDP 上的隐式报文**（避开 TCP 开销） | **从站 ESC 芯片硬件处理，报文"飞过"时就地读写** |
| 拓扑 | 星型/环型 | 星型 | **线型/环型/树型**（很灵活） |
| 一句话记忆 | 西门子的"实时以太网" | 罗克韦尔的"基于 CIP 的以太网" | "报文不停留、芯片处理、最快" |

> 📌 **注意一个坑**：**Profinet 用的是"以太网帧类型 0x8892"，不走 TCP/IP**；
> **EtherNet/IP 的 I/O 数据走 UDP 而非 TCP**。**所以它们能和普通网络"共线"但需要交换机支持 QoS/优先级。**

## 五、工厂常用信息系统（一句话各一）

| 系统 | 全称 | 管什么 | 谁用 |
|---|---|---|---|
| **SCADA** | 数据采集与监视控制 | 实时画面、报警、历史曲线、报表 | 中控室值班员 |
| **HMI** | 人机界面 | 单机/单线的操作屏（往往含在 SCADA 里） | 现场操作工 |
| **MES** | 制造执行系统 | **工单下达、批次追溯、质量判定、设备 OEE、物料防错** | 生产/质量/计划 |
| **EAM / CMMS** | 企业资产管理 / 计算机化维护管理 | **设备台账、保养计划、备件库存、维修工单、故障知识库** | 设备科/维修班组 |
| **ERP** | 企业资源计划 | 采购、销售、库存、财务、成本 | 经营层 |

**关系一句话**：
> **ERP 决定"做什么"（订单）→ MES 决定"怎么做"（工单/工艺/追溯）→ SCADA 看"做得怎么样"（实时）→ EAM 管"设备别坏"（保养维修）。**
> 底下是 **PLC 控制**，再底下是**现场设备**。

## 六、⭐ 10 个高频面试题 + 答法

### Q1. Modbus TCP 和 Modbus RTU 有什么区别？
> **报文结构一样（PDU 相同），只是"外壳"不同**：RTU 加地址+CRC 走串行；TCP 加 **MBAP 头（7 字节，含事务号/协议号/长度/单元号）** 走 TCP 502 端口。
> **事务号**是 TCP 版新增的 —— 因为一条 TCP 连接可以并发多个请求，靠事务号配对。

### Q2. Modbus 有什么缺点？
> ① **没有语义**（只有地址，靠手册约定）② **主从轮询**，从站不能主动上报，实时性差 ③ **没有认证/加密** ④ 功能码有限，不支持复杂数据结构。
> **但它赢在"简单 + 跨厂商 + 免费"** —— 采集场景够用。

### Q3. 为什么不全部用 OPC UA？
> **OPC UA 不是为实时控制设计的**（毫秒~百毫秒级），而且**实现重**（证书、会话、信息模型）。
> **实时控制用 Profinet IRT / EtherCAT；跨系统集成用 OPC UA。** 两者分工。

### Q4. OPC UA 的"信息模型"到底是什么？
> 它把设备抽象成**对象树**：对象有**变量**（带类型/单位）、有**方法**（可调用）、有**类型定义**（可以继承）。
> 客户端可以**浏览（Browse）** 出整棵树，**不需要提前知道地址**。这是它和 Modbus 的本质差别。

### Q5. SCADA 和 MES 区别？
> **SCADA 看现在**（实时状态、报警），**MES 管过程**（工单、批次、质量、追溯）。
> SCADA 面向"值班员"，MES 面向"生产管理者"。

### Q6. 设备数据采集你会怎么做？
> **分层**：现场协议（Modbus/Profinet）→ 采集端（我写的 Java 主站）→ 时序库（TDengine）→ 展示（SCADA/页面）。
> **三个必做**：① **质量码**（断线不能补 0）② **数据新鲜度**（采集端挂了要能看出来）③ **点表配置化**（换设备不改代码）。

### Q7. 现场设备读不到数据，你怎么排查？
> **按依赖顺序逐层确认**（我栽过跟头）：
> **① 物理（接线/供电/共地）→ ② 电平（A/B 有没有反）→ ③ 参数（波特率/校验/从站地址）→ ④ 数据（寄存器地址/类型/字序）**
> ⚠️ 我在这个顺序上犯过错：A/B 还没接就扫了 16 组参数，全白扫。

### Q8. 什么叫"设备通信网络运行监测"？
> 不是"能读到就行"，而是**持续监控链路健康度**：**成功率、延迟分位（P95/P99）、超时次数、异常码分布、重连次数**。
> 我在采集端做了：**每台设备的通信失败轮次、延迟直方图、质量码占比**。

### Q9. 你知道哪些 PLC 品牌？各有什么特点？
> **西门子**（S7-1200/1500 + TIA Portal，国内装机量最大）· **罗克韦尔**（ControlLogix/CompactLogix + Studio 5000，北美主流）· **三菱**（FX/iQ-R + GX Works，日系，中国市场大）· **欧姆龙**（NJ/NX）· **国产**（汇川、禾川、信捷 —— **很多底层是 CODESYS 内核**）· **倍福**（TwinCAT，基于 CODESYS，PC 控制）。

### Q10. 你们的系统怎么和上层（MES/ERP）对接？
> ① **协议层**：OPC UA（标准）/ 数据库中间表 / REST API ② **数据层**：MES 关心的是"工单-批次-设备-参数"的关联，不是我这种"点位时序"。
> **我需要把采集的时序数据按"批次/工单"聚合后再送上去** —— 这就是"采集"和"集成"的差别。
