# 明天开录前的模拟演练（约 30 分钟）

> 目的**不是"演得好"**，而是在录之前把"明天会卡在哪"找出来。
> 写在 2026-10-30 晚。配套执行单：`docs/录屏流程-3分钟.md`

---

## 零、先做一处架构调整（**必须，否则视频自相矛盾**）

### 问题

今晚之前，两条链是**分开**的：

```
真传感器(COM7) ──> Java 采集 ──> TDengine ──> 平台      ← 吹风机只影响这条
测试桩(COM5)   ──> CODESYS PLC 判断 ──> 1503 ──> Java  ← xAlarm 只受这条影响
```

结果就是：**吹风机吹热真表，`xAlarm` 纹丝不动** —— 录出来观众会觉得"你这俩没关系"。

### 改法：合并成一条链

```
真传感器(COM7) ──RS485──> [CODESYS PLC：Modbus RTU 主站]
                                    ├── rTemp / xAlarm（PLC 判断）
                                    └──Modbus TCP 1503──> Java ──> TDengine ──> 平台
```

**一个来源、一条链**：吹风机 → PLC 的 `rTemp` 涨 → `xAlarm` 翻 TRUE → 平台曲线同时涨。

### 操作（5 分钟）

| # | 在哪 | 做什么 |
|---|---|---|
| 1 | 物理 | **插上真传感器**，确认 `[System.IO.Ports.SerialPort]::GetPortNames()` 里有 **COM7** |
| 2 | CODESYS | 双击 `Modbus_COM` → **COM 端口 5 → 7** → 确定 |
| 3 | CODESYS | `在线 → 登录`（重新下载/启动，让主站用新串口） |
| 4 | 终端 | 如果 `RtuSlaveMain`（COM6 测试桩）还开着，**停掉**（不再需要） |
| 5 | CODESYS | 在线视图看 `wTempRaw` 应≈室温×10（如 24.7℃ → 247），`rTemp` ≈ 室温 |
| 6 | 平台 | `run-all.cmd` 已含 `plc-01` 采集；页面上 `plc-01` 的温度应≈室温 |

> 冒烟测试：**对着传感器吹 5 秒**，CODESYS 的 `rTemp` 应明显上升；松开后缓慢回落。

### 如果 `rTemp` 一直是 0

按这个顺序查（**不要跳步**）：

1. `Modbus_COM` 的 COM 端口是不是真的改成了 7
2. 通道 `偏移 0 / 长度 2` 有没有变
3. 从站地址是不是 1
4. 波特率 9600、数据位 8、**校验「无」**、停止位 1
5. `Modbus_Server_COM_Port` 的「状态」页看错误码

> 真表是 `9600-8-N-1 / 从站 1 / FC03 / offset0=湿度、offset1=温度（×0.1）`，这些 10-28 已实测过，理论上不用再改。

## 一、演练 A：冷启动计时（5 分钟）

```
stop-all.cmd      ← 等 10 秒，确认端口都释放
run-all.cmd
```

| 记什么 | 为什么 |
|---|---|
| TDengine 多久可连（6030 通） | 决定开录前提前多久启动 |
| 平台多久能打开（8080） | 别在镜头前干等 |
| 页面多久出现第一个数据点 | 决定"先启动再开录"的提前量 |

**经验值**：`run-all.cmd` 内部已经 sleep 了约 35 秒；**开录前至少提前 2 分钟启动**，让数据先跑出几条曲线（空图不好看）。

## 二、演练 B：走位计时（15 分钟，不录）

按执行单的 6 段，**只走位、只念口播、掐表**，不录屏。

| 段 | 计划时长 | 实际 | 卡在哪 | 改法 |
|---|---|---|---|---|
| 1 开场（平台页面） | 0:20 | | | |
| 2 南向（传感器 + 吹风） | 0:30 | | | |

3. **总时长** → 目标 **2:50**；超了先砍段 5

## 三、演练 C：故障注入（10 分钟，这是最值钱的一段）

录屏最怕"平时好好的，一录就坏"。提前**故意弄坏它**，看自己能不能救：

| 注入什么 | 预期现象 | 练什么 |
|---|---|---|
| 停掉采集端 15 秒 | 平台设备变灰 / 显示"数据过期" | 段 4 的台词；也证明系统真的有新鲜度判断 |
| 拔掉 COM7 | CODESYS `rTemp` **保持最后值**、`xAlarm` 不动；平台值不变但**时间戳变旧** | 讲"这就是 STALE，不是 0" |
| 插回 COM7 | 因为勾了「自动重启通信」，主站应**自行恢复** | 讲"通信要能自愈，不能靠人重连" |
| 把吹风机离远（温度上不去） | `xAlarm` 不翻 | 练预案：靠近 5cm、吹 8 秒 |

> 这三个故障对应的正是你项目里最强的三个卖点（质量码 / 新鲜度 / 自愈）。**演练时把它们演一遍，明天录的时候才敢讲。**

## 五、明天开录的 Go / No-Go（四条全过才开录）

- [ ] 吹风机 **8 秒内** `rTemp` 上升 **≥ 2℃**
- [ ] `xAlarm` 能 **FALSE → TRUE**，松手后能 **TRUE → FALSE**（回差恢复）
- [ ] 平台 **3 秒内**反映变化（曲线或数值）
- [ ] 全链**没有报错窗口**（CODESYS 状态页、采集端控制台、平台后端）

**任何一条不过 → 先修，别硬录。** 硬录出来的片子，一眼假。

## 六、如果真传感器明天出问题（兜底）

| 情况 | 兜底做法 |
|---|---|
| COM7 不出现 | 换 USB 口 / 换线；仍不行就**退回测试桩方案**（COM5 + `RtuSlaveMain`），并在口播里明说"这一段用模拟从站演示" |
| 读数一直 0 | 先查 8-N-1 和从站号，再查 A/B 线接反（对调试一次） |
| 温度上不去 | 用**热水杯**（40~50℃）靠近传感器，比吹风机稳 |
| `xAlarm` 不翻 | 阈值是 32；确认 `rTemp` 真超；超了不翻就重新登录 PLC |

> **诚实兜底**：真出问题，视频里就明说是模拟从站。**说得清边界**比"装成真表"安全得多。
