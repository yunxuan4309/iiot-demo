八个坑 each one is “I thought X, actually Y”

0
假数据一眼假
random() 是锯齿；真信号要有惯性＋漂移＋尖峰＋采样抖动
1
寄存器字序
Modbus 不规定 32 位怎么拆；四种字节序，国内仪表常见 CDAB
2
40001 vs offset 0
1 基惯用编号 vs 0 基协议地址；混了不是读错值，是永远超时（报文 9C 41）
3
断线不是 0
补 0 比没数据更危险 → 必须显式标 STALE（旧值）/ BAD（无值）
4
写操作不幂等
触发型写重发会执行两次；本 demo 只有线圈置位（天然幂等），只记录、未制造
5
单设备拖垮采集
线程 / 连接 / 时间三重隔离（每设备独立 driver，因 read() synchronized）＋ 退避
6
时间基准
TDengine 存 UTC、返回带 Z；不转时区整张图偏 8 小时。采集端用 epoch 毫秒
7
告警泛滥
已实现去抖＋回差＋分级＋质量码门禁；A/B 实测 86 条 → 12 条（压掉 86%）

技术栈与取舍 stack & trade-offs

Java 21 · 虚拟线程处理 100 设备 j2mod · 主站+从站一体 纯文本点表 · 点位约定不进代码 TDengine · 超级表贴合设备×点位 REST 而非 JDBC · 免 native 库，可跨隧道 Spring Boot 3.2 · 只读平台 ECharts 本地副本 · 离线可跑

边界 honest limits

不是生产系统（单机 · 无认证 · 无高可用 · 无联锁） │ 真传感器尚未接入：当前用仿真从站验证协议链路，RtuModbusDriver 接口已留 │ 北向 MQTT 未实现：页面走 HTTP，架构预留 iiot/{device}/{point} topic 规范 │ 告警只做判断不做通知：引擎已实现并 A/B 验证，但短信/企微与同源合并未做 │ 只有 4 个点位，够验证链路、不够覆盖真实产线
