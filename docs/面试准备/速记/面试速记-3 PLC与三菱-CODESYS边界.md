# 速记 3 · PLC / 三菱 / CODESYS · 边界怎么说

---

## 一句话分工

> **PLC 采集与判断（现在），Java 搬运与留存（过去和远方）。**

理由：服务器会挂、网会断、JVM 会 GC 停顿 —— **保护不能依赖服务器**。

---

## PLC 里到底做了什么（能背出这几行就够）

```iecst
wHumidityRaw := %IW10;
wTempRaw     := %IW11;
rHumidity    := WORD_TO_REAL(wHumidityRaw) / 10.0;
rTemp        := WORD_TO_REAL(wTempRaw) / 10.0;
xAlarm       := rTemp > 32.0;
```

**三个数证明"判断在 PLC"**：
- `wTempIn = 0` ← 以前 Java 灌数据的通道，现在没参与
- `wTempRaw = 356` ← PLC 从串口读回的原始寄存器
- `rTemp = 35.6`、`xAlarm = TRUE` ← PLC 算的

---

## 真表实测（2026-10-31）

`rTemp ≈ 22.5`（室温）→ **吹热风** → `rTemp ≈ 35.6`、`xAlarm` 翻 **TRUE** → 松手回落、报警解除。

> 讲法：**"先虚拟后真表"** —— 10-30 用 com0com（COM5↔COM6）把链路跑通，10-31 真表接回**只改了一个串口号**（5→7）。
> **这是加分项：没有硬件时也能把链路打通。**

---

## 三个真实卡点（一定要讲）

| 卡点 | 现象 | 原因 |
|---|---|---|
| **串口独占** | Java 打不开 COM7 | PLC 已占用；485 口通常只接一个主站 → **二选一** |
| **校验位默认 EVEN** | 连接成功但**每次读都超时** | 传感器是 `NONE`，必须改成"无" |
| **主从加反** | 怎么配都不出数 | `Modbus Serial Device` 是**从站**；要加 `Modbus Client, COM Port` |

## 三菱 GX Works2：做了什么、不能做什么

**做了**：FX3U 梯形图 `[D0 > K32] --- (Y0)`，GX Simulator 写 `D0=40` → `Y0` 导通（**蓝色**），写 20 → 断开。

**不能做**：**GX Simulator 没有对外通信口，也没有数据接口** → 只能验证逻辑，**采不了数据**。
（真 FX3U + 485BD 板可以，但要买硬件 —— 所以我改用 CODESYS。）

## CODESYS：软 PLC 的边界（主动说）

| 有 | 没有 |
|---|---|
| 真的 **Modbus RTU 主站** | 硬实时（Windows 上的软运行时） |
| 真的 **Modbus TCP 从站（1503）** | I/O 电气隔离 |
| 真的 **OPC UA 服务端（4840）** | 断电保持 |
| LD / ST / FBD 三语言 | 工业级可靠性 |

> 一句话：**"协议栈是真的，实时性和 I/O 不是。"**

---

## OPC UA 一句话讲清

- **Modbus 是编号**：第 3 个保持寄存器是什么，得看图纸
- **OPC UA 是自描述**：变量有名字、类型，客户端 **Browse** 就能发现

实测节点：`ns=4;|var|CODESYS Control Win V3 x64.Application.PLC_PRG.rTemp`

**坑**：符号配置没勾 → 看不到；勾了**没重新下载** → 还是看不到；匿名被拒 → 要开"允许匿名登录"。

## 三语言为什么都写了（同一逻辑三处实现）

LD 写报警回路、ST 写换算、FBD 写逻辑 —— 三个 POU 挂在同一个任务下，**在线同真同假**，用来证明"三种语言我都能落地"。
