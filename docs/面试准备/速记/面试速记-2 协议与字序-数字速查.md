## 四种字序（会画就会讲）

| 名称 | 32 位 `0x4278DECC` 拆两寄存器 |
|---|---|
| ABCD | reg0=`42 78`，reg1=`DE CC` |
| **CDAB** | reg0=`DE CC`，reg1=`42 78`（国内仪表常见） |
| BADC | reg0=`78 42`，reg1=`CC DE` |
| DCBA | reg0=`CC DE`，reg1=`78 42` |

**配错的两个方向**：
- 按 ABCD 解 CDAB 的字节 → `-7.36e18`（天文数字）
- 另一帧 → `1.88e-31` ≈ **0.00**（看起来像正常值，最阴）

---

## 抓包实证（一帧两种字序）

```
00 2f | 00 00 | 00 0b | 01 | 03 | 08 | de cc  42 78  00 00  04 d2
                                 reg0    reg1    reg2    reg3
```
- `reg0+reg1` 按 **CDAB** → `0x4278DECC` ≈ **62.2℃**
- `reg2+reg3` 按 **ABCD** → **1234 h**

## 40001 vs offset 0

- 手册的 `40001` = **1 基惯用编号**，报文里传 **0**
- 混了的表现：**不是读错值，而是永远超时**（报文里出现 `9C 41` = 40001）

## 采集侧设计（三句话）

1. **点表外置**：区域 / 偏移 / 类型 / 字序 / 量程，代码里没有设备私有约定
2. **每设备一条虚拟线程** + 读超时 + 退避 **1/2/4/8 倍、30s 封顶**（三重隔离：线程/连接/时间）
3. **质量码**：GOOD / STALE（沿用旧值）/ BAD（超量程、NaN）
