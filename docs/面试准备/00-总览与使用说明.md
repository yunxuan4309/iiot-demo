# 工业数据采集项目 · 面试准备 · 总览

> **项目**：`D:\java\iiot-demo` —— 真 RS485 传感器 → CODESYS 软 PLC（Modbus RTU 主站 + 判断）→ Modbus TCP 1503 → Java 采集 → TDengine → Spring Boot 平台；北向 MQTT / OPC UA；Wireshark 抓包验证。
> **定位**：面向「工业软件工程师 / 设备数据采集」岗位的**主项目**（对应 JD 职责 4、6 与资格 3、4）。
> **纪律**：本册所有数字与结论都能在仓库里找到出处（`docs/` 下各文档、代码、抓包文件）。**不编数据、不吹"生产级"**。

## 与电商项目的差异（面试必讲）

| 维度 | CoolShark 电商 | 工业采集（本项目） |
|---|---|---|
| 核心 | 高并发 + 事务一致性 | **数据可信 + 设备通信** |
| 通信 | HTTP / Dubbo | **Modbus RTU/TCP、OPC UA、MQTT** |
| 存储 | MySQL + Redis + ES | **TDengine 时序库** |
| 编程语言 | Java 为主 | **Java + IEC 61131-3（LD/ST/FBD）** |
| 数据特征 | 用户请求，可重试 | **采样值，断了就是断了（STALE）** |
| 失败代价 | 下单失败可重试 | **误报警 / 误联锁，可能停机** |

> 面试话术：
> 「电商教会我**吞吐和一致性**，工业项目教会我**数据可信和边界**。这两个能力不冲突——工业平台的后端，本质上也是高可用 + 数据治理，只是把'一致性'换成了'可信度'。」

---

## 三条主线（所有回答都往上靠）

1. **协议是真的**：真传感器 + 真 RS485 + 真 Modbus 报文（抓包为证）+ PLC 真当主站/从站 + OPC UA 真能 Browse。
2. **数据是可信的**：质量码 / 量程校验 / 新鲜度判定 / 告警去抖，都有实测数字。
3. **边界是清楚的**：软 PLC 不是硬 PLC、三菱只用仿真器、没做认证与高可用、只有 4 个点位 —— **主动说，比被问出来强**。
