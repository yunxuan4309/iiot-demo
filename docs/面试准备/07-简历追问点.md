## A. 工业项目（5 条，重点中的重点）

### A1 简历原文
> 真 RS485 温湿度变送器（艾克姆 IKM10000WS01 · 9600-8N1 · 从站 1 · FC03 · offset0=湿度 / offset1=温度，均 ×0.1）接入 CODESYS 软 PLC；PLC 作 Modbus RTU 主站读取并判断（`xAlarm := rTemp > 32.0`），再以 Modbus TCP 从站（1503）供上位机读取。

**追问 1：为什么不直接用 Java 读串口？**
骨架：一开始就是这么做的（能跑），但**不符合真实工业分层**。真实产线里传感器接 PLC，PLC 采集、PLC 判断，上位机只读结果。所以我改成 PLC 当主站，Java 只读 PLC。
加一句：串口是**独占**的 —— PLC 占了 COM7，Java 根本打不开，这个约束本身就逼着你选边。

**追问 2：PLC 里怎么判断的？**
骨架：`rTemp := WORD_TO_REAL(%IW11) / 10.0;` 然后 `xAlarm := rTemp > 32.0;`，阈值 32℃。报警位映射到 `%QX0.0`，上位机用 FC02 读离散输入。

**追问 3：怎么证明"采集和判断都在 PLC"？**
骨架：三个数 —— `wTempIn = 0`（以前 Java 写进来的通道，现在完全没参与）、`wTempRaw = 356`（PLC 从串口读回的原始寄存器）、`rTemp = 35.6` / `xAlarm = TRUE`（PLC 算的）。
再补一句：吹热风它就涨，松手就回落，全程 Java 没参与判断。

**追问 4：软 PLC 和真 PLC 差在哪？**
骨架：硬实时、I/O 隔离、断电保持、工业级可靠性都没有。但 **Modbus RTU 主站、Modbus TCP 从站、OPC UA 服务端都是真的**。
底线：**"我的 PLC 是软的，但协议栈和寄存器映射是真的；我不说自己做过产线 PLC。"**

### A2 简历原文
> 设备抽象层 `DeviceDriver`（TCP / RTU 两套实现）；点表把区域/偏移/类型/字序/量程外置；自写 Modbus 从站仿真器造 100 台设备压测；Wireshark 抓 FC03 逐字节核对，定位"同一帧两种字序"。

**追问 1：为什么要有设备抽象层？**
骨架：换协议不改上层。新增一种协议 = 新增一个 `DeviceDriver` 实现 + 一套点表，采集调度、质量码、入库全都不用动。

**追问 2：点表里都配了什么？**
骨架：`area`（holding/input/coil/discrete）、`offset`（0 基）、`type`（int16/uint16/float32/uint32/bool）、`order`（字序）、`min/max`（量程）、单位。**代码里没有任何设备的私有约定。**

**追问 3：字序为什么必须按点位配？**
骨架：因为**同一帧里就可能有两种**。实测：`reg0/reg1` 按 CDAB 才是温度（62.2℃），`reg2/reg3` 按 ABCD 才是运行时长（1234h）。配错的后果：变天文数字（-7.36e18），或者变成 0（1.88e-31）。

**追问 4：为什么要自己写从站？**
骨架：**没有 100 台真设备，但要验证 100 台时的表现**。j2mod 主站+从站一体，我用它造了 100 台仿真从站，跑 1 Hz 压测。顺带能用虚拟串口验证 RTU 驱动（不用等真表到货）。

**追问 5：Wireshark 怎么抓的？**
骨架：Npcap 回环抓 127.0.0.1 的 502（或 1502 + Decode As）。**坑**：Wireshark 默认只把 502 当 Modbus；1502 要 Decode As，而且解码器名是 `mbtcp` 不是 `modbus`。

### A3 简历原文
> 质量码 GOOD/STALE/BAD，断线保留上次值并标 STALE、绝不补 0，量程校验兜底字序配错；每设备一条虚拟线程 + 读超时 + 指数退避（1/2/4/8 倍，30s 封顶）；100 台×4 点×1Hz 压测：完整率 100%、388 点/秒、P50 1.27 ms / P99 9.95 ms、失败与丢弃 0/0；断线演练完整率平滑降到 61.5%、采集器不崩。

**追问 1：为什么不能补 0？**
骨架：0℃ 是合法值，下游会当真值 → 误判"运行正常"，或者反过来误触发。**宁可说"不知道"，也不给一个看起来正常的假值。**

**追问 2：STALE 和 BAD 区别？**
骨架：STALE = 这次没读到、值沿用上一次；BAD = 读到了但不可信（超量程、NaN、字序错）。

**追问 3：退避为什么是 1/2/4/8、还要 30 秒封顶？**
骨架：失败不该立刻重试（会打爆从站），也不该无限退（恢复太慢）。1/2/4/8 是二倍递增，30 秒封顶保证最长 30 秒必探一次。

**追问 4：100 台怎么保证不互相拖累？**
骨架：三重隔离 —— **线程**（每台一条虚拟线程）、**连接**（每台独立 driver，因为 Modbus 客户端 `read()` 是同步的）、**时间**（读超时）。一台卡死不影响其他。

**追问 5：P99 9.95ms 是什么的延迟？**
骨架：单次采集（读 4 个点位并完成解码）的耗时分布，不含写库。**别把它说成端到端延迟**（端到端是秒级：1 Hz 采集 + 批量 500ms + 页面 3 秒刷新）。

### A4 简历原文
> TDengine 3.3（超级表 + 每「设备×点位」子表），REST 批量写（500 点 / 500 ms，队列满丢点计数而不阻塞）；Spring Boot 只读接口 + ECharts，含数据新鲜度（ageSeconds / stale）与 TDengine 故障 503 降级。

**追问 1：为什么用 TDengine，不用 MySQL？**
骨架：数据是"持续产生、按时间查"的时序数据；超级表+子表天然贴合"设备×点位"；写入批量、压缩率高。

**追问 2：为什么走 REST 而不是 JDBC？**
骨架：免 native 库（Windows 装不了服务端，服务端在 WSL2）、可跨 WSL/SSH；返回自带 `column_meta`，解析简单。

**追问 3：队列满了为什么丢点而不是阻塞？**
骨架：**采集不能因为存储慢而停**。丢点有计数器（`droppedPoints`），指标能看到，比"整个采集卡死"好。

**追问 4：503 降级是什么？**
骨架：TDengine 不可用时，接口返回 503 + 可读 JSON，而不是 500 堆栈。前端能显示"数据源不可用"，而不是白屏。

### A5 简历原文
> MQTT（QoS 1 · retain）按 `iiot/{device}/{point}` 分发；PLC 侧开 OPC UA 服务端（4840），客户端无需点表、Browse 即可发现 rTemp/xAlarm；三菱 GX Works2 侧用 LD 实现同一报警逻辑并在仿真器验证。

**追问 1：MQTT 为什么 retain？**
骨架：新订阅者一上线就拿到最新值，不用等下一个采集周期。

**追问 2：OPC UA 和 Modbus 什么关系？**
骨架：不是替代，是互补。**Modbus 只有编号**（第 3 个保持寄存器是什么，得看图纸）；**OPC UA 是自描述**（变量有名字、类型、能 Browse）。
加一句：所以对接 MES/SCADA 时，对方能 OPC UA 就优先 OPC UA。

**追问 3：三菱那条你实际做了什么？**
骨架：GX Works2 → FX3U → 梯形图，`[D0 > K32] --- (Y0)`，仿真器写 `D0=40` → `Y0` 导通（GX 里是**蓝色**）；写 20 → 断开。
**关键补充**：GX Simulator **没有对外通信口**，所以它只能验证逻辑，采不了数据 —— 这也是为什么数据链路走 CODESYS。

## B. 电商项目（3 条，会被问"和工业有什么关系"）

| 简历要点 | 可能追问 | 答题骨架 |

| AI 导购：Function Calling 手写循环、3 个只读工具、3 轮上限强制收口、56 项离线测试 | 为什么不用 Spring AI？ | 卡 Boot 代际（项目 3.2.5 低于其支持下限）；而且"一个循环 + 一份工具清单"足够，引框架反而不可控 |

**跨项目追问**：「电商和工业，你觉得哪个难？」
骨架：**难点不同**。电商难在并发与一致性（可重试）；工业难在**不可重试** —— 采样错过就是错过了，只能靠质量码诚实标注。后者更考验"对失败的表达能力"。

## D. 三个"必被问"的通用题

**Q：这个项目最难的地方是什么？**
> 「不是写代码，是**判断哪些'看起来正常'的数据其实是错的**。字序配错不报错、断线补 0 不报错、采集进程挂了两天前的 GOOD 也不报错。所以我把力气花在'让错误可见'上：质量码、量程校验、新鲜度、抓包核对。」

**Q：如果给你真实产线，你要补什么？**
> 「五件：① 冗余（双机/双网）② 安全联锁 ③ 权限与审计 ④ 时钟同步（NTP/PTP）⑤ 断网缓存与补传。这五件我现在都没做，是明确知道的缺口。」

**Q：你最大的不足？**
> 「没在真实产线上待过。我做过的是**实验室条件下的完整链路**：真传感器、真协议、真报文、真时序库，但规模只有几个点位、没有产线干扰。所以我现在能讲清'协议和数据怎么走'，但不敢说'我能独立维护一条产线'。」
