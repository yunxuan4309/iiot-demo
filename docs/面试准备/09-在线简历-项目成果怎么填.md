# 09 在线简历 · 「项目成果」怎么填

> 网申系统常有「项目成果 / 项目业绩 / 项目描述」字段，限制 200~1000 字。
> **HR 和 ATS 只看两样：可验证的结果 + 量化数字。** 别写成职责复述。

---

## 一、填写公式

```
做了什么（一句话，说清技术链路）
→ 结果（数字，越多越好，但必须真实）
→ 交付物（可查证：仓库 / 文档 / 博客 / 视频）
```

**反面例子**（网申里最常见、也最没用）：
- ❌「提升了系统的稳定性和可维护性」
- ❌「加深了对工业通信协议的理解」
- ❌「负责项目的整体设计与开发」

**正面例子**：
- ✅「100 台×4 点位×1 Hz 压测，完整率 100%（24000 点）、388 点/秒、P99 9.95 ms」

---

## 二、工业项目（长版 ≈ 330 字，适合 500~1000 字字段）

```
独立完成工业设备数据采集与在线监测 Demo 的全链路搭建：真 RS485 温湿度变送器（艾克姆 IKM10000WS01，9600-8N1，从站 1，FC03）接入 CODESYS 软 PLC，PLC 作 Modbus RTU 主站完成采集并在 PLC 内判断报警（rTemp > 32.0）；Java 采集端通过 Modbus TCP（1503）读取结果，写入 TDengine 时序库，由 Spring Boot + ECharts 页面展示；北向提供 MQTT 与 OPC UA 两种接口。
主要成果：
1. 性能：100 台 × 4 点位 × 1 Hz × 60 s 压测，采集完整率 100%（24000 点）、入库 388 点/秒、延迟 P50 1.27 ms / P95 4.14 ms / P99 9.95 ms，写入失败与队列丢弃均为 0；
2. 可靠性：断线演练中完整率由 100% 平滑降至 61.54%，数据保留上次值并标记 STALE（绝不补 0），采集器不崩溃；
3. 可维护性：点表把区域、偏移、数据类型、字节序、量程全部外置，更换仪表只改配置不改代码；用 Wireshark 抓取 FC03 报文逐字节核对，定位到"同一帧内两种字节序"（温度 CDAB、运行时长 ABCD）；
4. 告警治理：实测 10 分钟 3 台设备产生 836 个越限采样点但仅 10 次真实越限事件（放大 83.6 倍），通过持续时间去抖、回差与分级抑制将告警从 86 条压到 12 条；
5. 交付物：开源仓库（含 PLC 工程与 45 篇技术文档）、3 篇技术博客、3 分钟演示视频。
```

## 三、工业项目（短版 ≈ 130 字，适合 200~300 字字段）

```
独立完成「真传感器 → PLC（Modbus RTU 主站）→ Modbus TCP → TDengine → Web」全链路。
100 台×4 点位×1 Hz 压测：完整率 100%（24000 点）、388 点/秒、P99 9.95 ms、失败与丢弃 0/0；
断线演练完整率 61.54% 且标 STALE 不补 0、采集器不崩；用 Wireshark 定位同一帧两种字节序；
告警去抖 86→12 条。交付开源仓库、3 篇技术博客与演示视频。
```

## 四、电商项目（长版 ≈ 320 字）

```
独立开发并长期运维 CoolShark 微服务电商平台（Spring Cloud，11 个微服务）。
主要成果：
1. 部署：用 Docker Compose 编排 21 个容器（MySQL / Redis / RabbitMQ / Elasticsearch / Nacos / 网关 / 11 个微服务 / 前端），Nginx 反向代理与前端托管；
2. 故障定位：压测 100 并发时 20% 请求返回 500，先以"数据库活跃线程仅 2~3"排除数据库，再依据"连接数恒为 8"定位到应用侧连接池未配置池大小并修复；另修复线上网关 502（按上游健康状态逐层定位）、Redis 主从不一致、Nacos 认证缺失、时区偏差，服务器内存占用由 93% 降至 71%；
3. AI 能力：上线 AI 导购模块，不引框架、用 Function Calling 手写"一个循环 + 工具清单"，3 个只读工具、最多 3 轮并用尽强制收口；56 项离线测试全部通过，线上用环境变量开关可回滚；
4. 版本与备份：新版本先在临时库与临时容器验证再切正式；每日 02:30 自动备份、保留 7 天，并做过一次独立临时库恢复演练；
5. 在线可访问（含前台与管理端），长期自行运维。
```

## 五、电商项目（短版 ≈ 120 字）

```
独立开发并运维 21 个容器的微服务电商（11 个微服务）。定位并修复压测 500（应用侧连接池未配池大小）、
网关 502、Redis 主从不一致、Nacos 认证缺失、时区偏差，内存占用 93%→71%；

每日备份保留 7 天并做过恢复演练。
```

## 七、五个常见坑

| 坑 | 怎么避 |
|---|---|
| 写成"职责清单" | 每条都以结果或数字结尾 |
| 数字前后矛盾 | 两个项目别出现同一个数字指两件事（比如 100 台 vs 100 并发） |
| 把"我参与"写成"我主导" | 个人项目写"独立完成"；实习写"负责/参与" |
| 写"提升了 X%" 但没有基线 | 只写你**真测过**的（完整率、P99、内存占比、告警条数） |
| 字段很短还硬塞长版 | 用短版；宁可少写，不要被截断成半句 |
