# 数据新鲜度检查（stale detection）

> 实测：**2026-10-24** · 上线后立刻抓到「10 台设备的数据已经 3 小时 16 分没更新」

## 一、问题：**采集端停了，库里仍然是 GOOD**

时序库存的是「**写进去那一刻的事实**」：

```
14:00:00  采集端写：sim-01 temperature=63.45 quality=GOOD
14:00:01  采集端写：sim-01 temperature=63.47 quality=GOOD
...
14:00:05  ⚠️ 采集端被杀（或网断、进程崩、机器重启）
          ↓
          之后再没有任何写入
          ↓
17:16:00  页面查询：最后一条 = 63.47 / GOOD
          ↓
          页面显示："63.47℃ 一切正常"   ← ❌ 骗人
```

**「采集端挂了」和「设备一直没变」在旧版页面上一模一样。**

> 现场的坑就是这样：**值班员以为系统正常，其实采集早挂了。**
> 大屏上"数字不动"比"数字错了"更危险 —— 因为错了会有人查，不动没人管。

---

## 二、实测证据（上线后第一次查询）

```
== /api/overview ==
  设备 11 台 · 过期阈值 15 秒 · ⚠ 过期设备 10 台

== /api/latest ==
  plc-01   年龄 0s        stale=False   ← 采集端在跑
  sim-01   年龄 11764s    stale=True    ← 3 小时 16 分没更新！
  sim-02   年龄 11764s    stale=True
```

上线立刻发现：那 10 台仿真设备的采集端早被我停掉了，但页面一直把它们当"当前值"显示。

---

## 三、为什么必须在「查询层」判断

| 层 | 能不能做 | 原因 |
|---|---|---|
| **采集端** | ❌ | 采集端自己挂了，就没法报告"我挂了" |
| **数据库 / 时序库** | ❌ | 存的是"写入那一刻的事实"，它不知道以后有没有人来写 |
| **查询 / 展示层** | ✅ **必须在这** | 只有"现在"这个时刻，才能判断"这条数据有多旧" |

> 📌 **监控系统通则**：**"数据是否新鲜"永远是读取方判断的，不是写入方声明的。**

---

## 四、实现

### 1. 阈值（可配）

`application.yml`：

```yaml
iiot:
  stale:
    after-seconds: 15      # 采样 1 秒的 15 倍，给网络抖动和短暂重连留余量
```

### 2. 接口返回两个新字段

`GET /api/latest` 的每个点位：

```json
{
  "val": 75.0, "ts": "2026-10-24T07:45:12.000Z", "quality": "GOOD",
  "ageSeconds": 0,          // 最新点距今多少秒
  "stale": false            // 超过阈值 → true
}
```

设备节点也会带一个 `stale`（**任一**点位过期 → 设备过期）。

`GET /api/overview` 多返回：

```json
{ "staleDevices": 10, "staleAfterSeconds": 15 }
```

### 3. 页面表现

| 位置 | 过期时 |
|---|---|
| 设备行温度 | **变灰** |
| 状态列 | **⚠ 数据过期 11764s**（琥珀色），**优先于"报警/运行/停机"** |
| 右上指标卡 | 数据最新时刻下方加一行 **⚠ 10 台数据已过期（>15s 未更新）** |

> **为什么"过期"优先于"报警"**：一个不动的旧值比一个报警更危险 ——
> 报警至少是"设备在说话"，过期是"**根本没人在说话**"。

---

## 五、和"质量码"的区别（别混）

| | **quality**（GOOD/STALE/BAD） | **stale**（新鲜度） |
|---|---|---|
| 谁产生 | **采集端**写入时判定 | **查询层**用当前时间判断 |
| 回答的问题 | 「这个值**采到的时候**可信吗？」 | 「这个值**现在还新吗？」 |
| 存哪 | **存进数据库**（是数据的一部分） | **不存**（查询时算出来） |
| 采集端停了会变吗 | ❌ **不会**（它再也不会写新记录） | ✅ **会**（时间过了就过期） |

**⇒ 两者互补，缺一不可**：`quality` 管"**数据本身可不可信**"，`stale` 管"**这条数据还活不活**"。

## 六、面试口径

> 「时序库里存的是'写入那一刻的事实' —— **采集端挂了，最后一条记录仍然是 GOOD**。
> 所以'**采集端停了**'和'**设备一直没变**'在数据库里长得一模一样，
> 页面如果不判断，就会变成一个**永远不动但看起来正常**的数字。
>
> 正确做法是**在查询层算 `ageSeconds`**：最新点距今超过 3~5 个采样周期就标成过期。
> 这个判断**不能放在采集端**（它自己挂了没法报告），**也不能放在数据库**（它不知道以后有没有人写）。
>
> 我实测的时候上线就抓到了：10 台设备的采集端已经停了 3 小时，页面之前一直显示'正常'，
> 加了新鲜度之后立刻变成 '⚠ 数据过期 11764s'。
>
> 还有一点要注意：**'质量码'和'新鲜度'是两件事** ——
> 质量码是**采集时**对数据可信度的判定（存进库里），新鲜度是**查询时**对数据时效性的判定（算出来的）。
> 一个采集端停了，库里的 quality 永远是 GOOD，只有 stale 能告诉你它死了。」
