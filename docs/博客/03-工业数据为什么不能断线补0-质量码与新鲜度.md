# 工业数据为什么不能"断线补 0"：聊聊质量码与数据新鲜度

> 在互联网系统里，"没数据"通常返回 `null`，前端显示个占位符就完事了。
> 但在工业监测里，**"0" 不是一个中性的占位符**——它可能是一个合法测量值，也可能被下游当成"设备温度正常"甚至"触发联锁"。
> 这篇讲我给这套采集链路加的三样东西：质量码、数据新鲜度、告警去抖。

---

## 一、一个真实的风险场景

假设温度传感器掉线了。

- **做法 A（错的）**：采集端读失败，写一条 `temperature = 0` 进库。
- **做法 B（对的）**：采集端读失败，写**上一次的值**，并标记 `quality = STALE`。

为什么 A 危险？

因为 0℃ 在北方冬天是**完全合理的室温**。下游做告警判断的代码会写 `if (t > 80) alert()` —— 0 不触发报警，看起来"一切正常"。
但如果下游有另一条规则，或者有人看报表，就会得到结论：**"这台设备今天一直是 0℃，运行正常。"**

**它没有告警，也没有数据缺失提示，但事实是：你什么都不know。**

> 所以我的处理原则只有一句：
> **宁可明确地"不知道"，也不要给一个看起来正常的假值。**

## 二、质量码：给每条数据打上"可信度"

每条点位值落库时都带一个质量码：

| 质量码 | 含义 | 典型场景 |
|---|---|---|
| **GOOD** | 本次读到、且在量程内 | 正常采集 |
| **STALE** | 本次没读到，**值是上一次的** | 通信超时、从站不响应 |
| **BAD** | 读到了但**不可信** | 解出来超量程（字序配错）、NaN/Inf |

实现上不复杂：采集器每个点位保留 `lastKnown`，读失败时沿用旧值并降级质量码，绝不写 0。

### 一个容易忽略的细节

`STALE` 是**采集端**在"读失败那一刻"打的。

但问题来了：**如果采集进程整个挂了呢？**

那库里就再也不会有新数据，最后一条永远是 GOOD —— 一个三天前的 GOOD。

## 三、数据新鲜度：过期只能在查询层判断

这是我这套设计里最关键的一个认知：

> **库里的质量码，是"写入那一刻"的判定。**
> **"这条数据现在还算不算数"，只有查询的时候才知道。**

所以我加了一层：平台查询最新值时，同时返回 `ageSeconds`（距今多少秒）和 `stale`（是否超过阈值，默认 15 秒）。

```json
{
  "device": "plc-01",
  "points": {
    "temperature": { "val": 22.5, "quality": "GOOD", "ageSeconds": 0, "stale": false }
  }
}
```

页面渲染的优先级也改了：

```
数据过期  >  报警  >  正常
```

**为什么"过期"要排在报警前面？**
因为一个不动的旧值比一个报警更危险 —— 报警至少说明系统还在看；过期说明**已经没人看了**。

实测：把采集端停 15 秒，页面上的设备立刻变灰、显示"⚠ 数据过期 15s"。这件事比任何架构图都更能说明问题。

## 四、告警去抖：别把"采样点越限"当成"事件"

这是另一个我实测出来的数字，挺震撼的：

> 10 分钟、3 台设备，共 **836 个越限采样点**，但真实越限事件只有 **10 次**。
> **放大 83.6 倍。**

原因很简单：温度在阈值附近抖动，每 1 秒采一次，就会反复"越限—恢复—越限"。

如果按采样点报警，运维一天会收到几百条微信，然后**把告警群静音** —— 这才是最危险的后果。

正确的做法是三层：

| 手段 | 作用 |
|---|---|
| **持续时间去抖** | 连续 N 次（或持续 X 秒）越限才算一次事件 |
| **回差（迟滞）** | 上阈值 32℃ 触发、回落到 30℃ 才解除，避免在阈值上反复横跳 |
| **分级抑制** | 同一设备同一类型的告警在时间窗内合并，只发一条 |

实现后，同样的数据从 86 条降到 12 条（压掉 86%）。

## 五、还有一个隐形坑：时间基准

TDengine 存的是 UTC，REST 返回带 `Z` 的时间戳。

前端如果直接当本地时间格式化，**整张图会偏 8 小时**（中国时区）。

我的处理：

- 采集端写库用 **epoch 毫秒**，避免字符串时区歧义；
- 前端统一用浏览器本地时区把 `Z` 时间转换后再画；
- 页脚明确写一句"数据来自 TDengine（UTC 存储，页面按浏览器本地时区显示）"。

看起来很琐碎，但这是"数据正确"的一部分 —— **时间错了，趋势就是错的。**

## 六、这三点背后的同一个想法

质量码、新鲜度、告警去抖，看起来是三件事，其实是同一件事：

> **工业软件的第一性要求不是"功能多"，是"数据可信"。**

因为工业系统的下游常常是**动作**：报警、停机、联锁、报表、结算。
一个不可信的数字流进去，出来就是一个错误的动作。

所以我在这个项目里养成了一个习惯：**任何一条数据，都要能回答三个问题**——

1. 这是**什么时候**的？（时间戳 + 新鲜度）
2. 这**可信吗**？（质量码 + 量程校验）
3. 这**是从哪来的**？（设备 → 点位 → 寄存器偏移，可回溯到点表）

---

## 七、如果只记一句话

> **断线补 0，是把"故障"伪装成"正常"。**
> **STALE 不是丢人，它是在诚实地说：我最后一次看到它，是在那一刻。**
