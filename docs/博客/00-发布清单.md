## 二、每篇的发布信息

### ① 字序篇
- **分类**：后端 / 工业互联网
- **标签**：`Modbus` `工业互联网` `协议` `PLC` `踩坑`
- **摘要**：Modbus 只规定寄存器 16 位，不规定 32 位怎么拆。四种字序里配错一个，温度会变成 -7.36e18 或者干脆变成 0.00 —— 而且它不报错。
- **封面**：可以用报文截图（`docs/modbus-fc03.pcapng` 在 Wireshark 里的样子）

### ② 质量码篇
- **分类**：后端 / 工业互联网
- **标签**：`工业互联网` `数据质量` `时序数据` `监控` `设计`
- **摘要**：断线补 0 是把故障伪装成正常。这篇讲我给采集链路加的三样东西：质量码（GOOD/STALE/BAD）、数据新鲜度（ageSeconds/stale）、告警去抖（836 个越限点其实只有 10 次事件）。

### ③ PLC 直读篇
- **分类**：工业互联网 / 编程语言（IEC 61131-3）
- **标签**：`PLC` `CODESYS` `Modbus` `三菱` `工业软件`
- **摘要**：我最初让 Java 直接读 485 传感器，PLC 在旁边"演一下报警"。后来发现这在工业上讲不通——于是把整条链拆了重做：传感器接 PLC、PLC 当 Modbus 主站、Java 只读 PLC。记录三个卡点和一条分工原则。
