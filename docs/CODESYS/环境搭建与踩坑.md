## 一、安装阶段的 3 个关键决策（都选对了，记下来避免重装时重新纠结）

### ① Repositories（库/设备描述文件放哪）

| 选项 | 含义 | 选择 |
|---|---|---|
| `no` — install to the standard folder (default) | 装到 `C:\ProgramData\CODESYS\...` | ✅ **选这个** |
| `yes` — separate folder, only for this installation | 独立目录，只给这次安装用 | ❌ 只在"一台机器装多个 CODESYS 版本"时才需要 |

> 理由：只装一个版本；标准路径兼容性最好（教程、排查都基于默认路径）。仓库约 1~2 GB，C 盘够。

### ② Select Packages（组件选择）

**界面规则（和直觉相反）**：
- **左侧空** = 不装（排除项为空 ⇒ 默认**全装**）
- **右侧满** = 要装
- 点 `>` 从左挪到右 = **加入安装**；点 `<` 从右挪到左 = **排除**

**移出这 6 个**（Windows 软 PLC 用不到）：

```
CODESYS Code Generator ARM 4.0.4.0
CODESYS Code Generator ARM64 4.0.2.0
CODESYS Code Generator Cortex M3 4.0.2.0
CODESYS Code Generator PowerPC 4.0.2.0
CODESYS Code Generator TriCore 4.0.1.0
CODESYS Compiler Versions Archive 4.0.0.0
```

**必须保留**：

| 包 | 作用 |
|---|---|
| `CODESYS Base Libraries` | 基础库 |
| `CODESYS Communication` | 通信 |
| **`CODESYS Modbus 4.6.0.0`** | ⭐ **Modbus 主/从站**（独立包，不在 Communication 里） |
| **`CODESYS Ladder` + `CODESYS LD FBD`** | ⭐ **梯形图 / FBD 编辑器** |
| `CODESYS Math Libraries` | 数学/比较功能块 |

> 📌 **发现**：`Control Win SL` **不在** Select Packages 列表里（按字母序 C 段被跳过）。
> 但它在**后面「Allow remote access」那一屏**出现了 ⇒ **运行时是随包装上的**，只是不作为"可选包"列出。

### ③ Allow remote access（是否在防火墙开洞）

**三个复选框全部不勾**（`CODESYS` / `CODESYS Gateway` / `CODESYS Control Win`）。

> 理由：官方文档明确警告「**任何情况下都不得从 Internet 访问控制器**」，编程端口是 **UDP 1740~1743 / TCP 1217 / 11740**。
> 只允许本机回环是最安全的配置；以后要远程，用 **Tailscale** 那类私有组网，而不是开防火墙。

## 二、连接链路是**三层**（排障必背）

```
① 网络连通          网关绿点 + 设备绿点
   ↓                （Gateway-1  localhost:1217）
② 会话建立          ← 这里失败 = `InvalidSessionId`
   ↓
③ 权限认证          ← 这里失败 = 「设备用户登录」要求输入账号密码
```

> ⭐ **每一层的错误"长得都不一样"**，这是排障能分清的前提。
> 面试可讲：「工业上位机连 PLC 要过**连通 → 会话 → 认证**三层，我做环境时三层各踩了一次。」

**关键参数（本机）**

| 项 | 值 |
|---|---|
| 网关 | `Gateway-1` · `localhost` · 端口 **1217** |
| 设备 | `<主机名>`（Windows 计算机名）· 设备地址 **`0001`** |
| 目标 ID / 类型 / 供应商 | `0000 0004` / `4096` / `CODESYS` |
| 目标版本 | **`3.5.22.40`**（与 IDE 完全一致 ⇒ 不会有"版本不匹配"类登录失败） |

## 三、踩到的坑（按发生顺序）

### 坑 0：**预判错了「家庭版不支持」**

- 我基于"工业软件普遍要专业版"的常识，预判家庭版 + 25H2 装不上、打不开。
- **实测：装得上、打得开、能编译、能下载、能在线监控。**
- **教训**：**环境类结论必须以实测为准，不能按"官方兼容性清单"推**。这是本轮第 3 次同类错误（另两次：误判"没装 Maven"、"RDB 没开"）。

### 坑 1：以为要单独下载运行时

- 现象：Select Packages 里翻到 `T` 都没见到 `Control Win`，据此推断"运行时被拆出去了"。
- 实际：它在后面「Allow remote access」那一屏**作为产品出现**，说明**已经装上**。
- **教训**：**"列表里没看到" ≠ "没有"** —— 同一份安装包的不同界面会展示不同粒度。

### 坑 2：软 PLC **默认不自启**

- 现象：登录时连不上设备。
- 原因：官方从 **V3.5 SP2** 起，`CODESYS Control Win` 运行时**出于安全考虑不随系统自启**。
- 解法：**托盘 `CODESYS ControlSysTray` → 右键 → 「启动 PLC」**（网关 `GatewaySysTray` 倒是自启的）。
- 首次启动会弹安全提示："允许以系统级权限执行代码，请限制网络访问" → **点 OK**。

### 坑 3：⭐ **密码策略踩雷**（`Admin123456` 被拒，确认按钮是灰的）

对话框红字明写两条策略：

| 策略 | 说明 |
|---|---|
| **密码必须包含特殊字符** | `Admin123456` 全是字母数字 ⇒ 违反 |
| **密码不能包含设备用户名** | 用户名 `admin`，密码含 `Admin` ⇒ 违反 |

- **换成含 `@` 且不含 admin 的密码后通过。**
- 📖 **这是真实的工业安全实践**：现场操作工的密码常见"用户名+123"，策略就是堵这个。
- 凭据本身 → 见同目录 `本机凭据-勿提交.md`（**已 gitignore**）。

### 坑 4：⭐ **`通讯错误: InvalidSessionId(#0x0000001C)`**

- 现象：在"添加设备用户"框里填完密码点确认 → 报 `InvalidSessionId`；随后又弹回"是否激活用户管理"。
- 根因：**填表太慢，会话已超时失效**，提交时用的是过期会话。
- **解法**：**把密码先复制到剪贴板，`Ctrl+V` 粘贴，立刻点确认**。
- **换个角度**：这也是"工业通信是**会话式**"的直接证据 —— 会话会超时、会失效，所以工程上要**自动重连 + 幂等**。

### 坑 5：`设备用户登录` —— "没有权限在该设备上执行此操作"

- 说明**用户管理已经激活**（第一次的创建其实生效了，只是会话失效）→ 此时要求输入账号密码。
- 填 `admin` + 密码 → 通过 → 提示下载 → 点「是」→ **下载成功**。

### 坑 6（观察，不是错误）：内存占用很小

编译日志显示：**数据区最高用到 27656 字节、代码区 79864 字节**（各 1 MB 预算）。

> 与 OpenPLC 那边"固件 16 KB 占 6%"互相印证：**PLC 程序本身极其精简** —— 这正是"PLC 不该存历史数据、不该做报表"的量化证据。

## 四、日常使用速查

| 要做什么 | 怎么做 |
|---|---|
| 启动软 PLC | 托盘 `CODESYS ControlSysTray` → 启动 PLC（**每次开机都要做**） |
| 登录 | `在线` → `登录`（先选中设备树里的 `Device` 节点，否则菜单可能是灰的） |
| 下载 | 登录时提示「是否下载」→ 是 |
| 运行 | `调试` → `启动`（F5） |
| 改值/强制 | 声明区双击值 → 输入 → **`Ctrl+F7`（写入值）** ← ⚠️ 双击只改"准备值"，必须再按写入才生效 |
| 停止 | `调试` → `停止` |
| 复位（会话乱了） | 托盘 **停止 PLC → 启动 PLC**，再重新登录 |

## 五、面试可选素材（这一路踩出来的）

1. **工业软件是"工具链"，不是"装个软件"**：安装组件选择 → 运行时 → 网关（1217）→ 会话 → 权限认证，一层都不能少。
2. **安全默认值处处体现**：远程访问默认不开、运行时默认不自启、密码强制复杂度。
3. **三层连接模型**（连通 / 会话 / 认证），错误现象各不相同 —— 这是排障方法论。
4. **PLC 程序极小**（代码区 79 KB），所以**历史数据必须放到上位机/时序库** —— 正好接上"为什么需要 Java 采集层"。
5. **同一段 IEC 61131-3 ST，OpenPLC 与 CODESYS 都能跑** —— 语言是标准，工具是外壳。
6. **准备值 / 写入值 / 强制值** 三者区别（见 §六）—— 说明"我不只是会点运行，我知道值是怎么下发的"。

## 六、三个"值"的区别（调试最容易混，2026-10-23 实操确认）

> 面试常问"你怎么改 PLC 里的变量"。答不清这三个，就是没真摸过。

| 概念 | 英文 | 含义 | 生效时机 | 典型用途 |
|---|---|---|---|---|
| **准备值** | Prepared value | 只是"**记下要写的数**"，**完全没有生效** | 不生效 | 先想好要写什么，避免手滑 |
| **写入值** | Write value（`Ctrl+F7` / `调试→写入值`） | **一次性**下发；**下一个扫描周期可能被程序逻辑覆盖** | 立即，但只到被覆盖为止 | 临时改一个输入量做测试 |
| **强制值** | Force value | **持续**强制，**程序逻辑改不动它**；必须显式"解除强制"才停 | 一直有效直到解除 | 模拟"传感器一直 90"这类锁死场景 |

### 实操撞到的现象

1. 双击变量值 → 弹「**准备值**」对话框 → 填 `90` → 确定
   → ⚠️ **这时"值"列根本不变**（还是 25）—— 因为只是预备。
2. 再按 **`Ctrl+F7`（写入值）** → **"值"列立刻变 90**
   → 程序下一周期算出 `xAlarm := 90 > 80` = **TRUE** ✅

### 该用哪个（判据）

> **程序只"读"这个变量**（如 `rTemp` 仅作为输入参与判断）⇒ **写入值就够**，写进去会一直保持。
> **程序会"写"这个变量**（如每周期都执行 `rTemp := 25;`）⇒ 写入值会被**立刻覆盖**，必须用 **强制值**。

📌 **一句话**：**准备值只是预备、写入是一次性、强制才不被逻辑覆盖。**
分不清这三个，调试时会一直以为"我改了怎么没用"。
